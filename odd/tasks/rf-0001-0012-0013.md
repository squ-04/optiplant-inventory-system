# RF-0001, RF-0012, RF-0013 — Minimum stock, local catalog and product units

Objective: change explicit per-branch minimums, show the session branch's local catalog and manage commercial units with exact conversion (Spring Boot + PostgreSQL + React).
Branch: `feat/rf-0001-rf0012-rf0013` from `main` 811944a. Delivery: work-unit commits, no push. Runners: Maven Docker runner (`backend/README.md`), `pnpm test` / `pnpm build`.

## Specs

- **S1 (RF-0001):** administrator changes the explicit minimum of an enabled product-branch combination; zero is valid (INC-010). Only `catalog_branch_product.minimum_qty` changes; stock, costs, documents and purchases do not. A non-enabled combination is rejected (`409 PRODUCT_NOT_ENABLED`).
- **S2 (RF-0012):** manager and operator see the products enabled in their session branch, including those without stock, with physical, available (= physical, glossary §5.3) and in-transit quantities kept separate, plus the minimum. The branch always comes from the session; the general catalog marks enabled/not enabled.
- **S3 (RF-0013):** administrator adds commercial units with a base-unit factor and changes the factor or availability. INC-007: at most 3 decimals, no silent rounding, base unit fixed once used, documents keep their snapshots. Invalid quantities are rejected without any movement.

Assumptions (derived, not new scope): units are keyed by name inside the product (no rename, no divisibility change, no migration); names compare case-insensitively; a base unit turning indivisible requires whole commercial units (`PRODUCT_UNITS_INCOMPATIBLE`).
