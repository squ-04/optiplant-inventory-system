# RF-0014, RF-0015 — Cross-branch inventory and shared freshness

Objective: consult the stock of any branch (physical, available and transit apart, no valuation) and keep it visibly fresh by REST polling with a stale-data warning (Spring Boot + PostgreSQL + React).
Branch: `feat/rf0014-rf0015` from `main` 638e5a8. Delivery: work-unit commits, no push. Runners: Maven Docker runner (`backend/README.md`), `pnpm test` / `pnpm build`, `scripts/run_checks.py all`.

## Specs

- **S1 (RF-0014):** «el sistema deberá permitir consultar el inventario de una sucursal distinta de la propia». «identificar sucursal, físico, disponible y tránsito separado (§5.3). Los tres roles consultan inventario autorizado de otras sucursales sin escritura cruzada; operador no accede a valoración/costos agregados.» RF-0014-CA-01: «dadas dos sucursales con existencias distintas, cuando un usuario consulte la otra sucursal, entonces verá el inventario de esa sucursal y no el de la propia.»
- **S2 (RF-0015):** «hacer visibles entre sucursales los cambios del inventario manteniendo coherencia». ARQ-PEN-003: polling REST con TanStack Query, intervalo inicial de dos segundos, reconsultar al recuperar conexión, foco o visibilidad, sin prolongar la inactividad. RF-0015-CA-01: «dado un movimiento confirmado en origen, cuando otra sucursal consulte ese inventario tras el intervalo aprobado, entonces observará las existencias actualizadas». RF-0015-CA-02: «dada pérdida de comunicación, cuando se muestren datos previamente consultados, entonces se advertirá su posible desactualización sin afirmar que una operación no aceptada quedó confirmada.»

Assumptions (derived, not new scope): no valuation for any role in this read (the matrix only forbids it for operators; omitting it for all avoids role-dependent payloads); rows include balances, active enabled products and pending transit towards the branch; the previous `/visibility/inventory/{uuid}` stays unchanged for compatibility.
