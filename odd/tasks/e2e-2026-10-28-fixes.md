## Specs

- **S1 (H1):** the sale confirmation never asks the operator to accept a total built from a stale price. Before opening the confirmation dialog the form re-reads the chosen price list; if any price of the draft changed, it shows the current prices and asks to review the total instead of confirming.
- **S2 (H2):** a price list deactivated while the sale form is open is reported as unavailable («ya no está disponible»), not as «no tiene precio»; the list of options is refreshed and the inactive list leaves the selector.
- **S3 (H3):** discount inputs (sales and purchases) accept only 0–100 with up to 6 decimals on the client; the confirmation dialog never shows «—» as an estimated total.
- **S4 (H4):** an input that does not match its format shows the field's own hint (its `title`) instead of the browser's generic «Haz coincidir el formato solicitado.».
- **S5 (H5):** managers and administrators get `403` on sale confirmation and on purchase writes before any body validation; operators keep the current validation messages.
- **S6 (H6):** purchase receipt texts agree in number («la línea» / «las N líneas»).
- **S7 (H7):** the «Venta de referencia» options of a customer return identify the sale by its code (`VT-…`).
- **S8 (H8, format decision):** dates and times use `dd/mm/aaaa, h:mm:ss a. m.` (four-digit year, 12-hour clock as usual in Colombia); due dates `dd/mm/aaaa`. Unit prices in COP show at least 2 decimals and keep up to 6 significant ones (`1.000,00`, `11.000,50`, `0,123456`); amounts keep 2 decimals; average costs keep 6. Server line messages read «Línea N: <minúscula>…» and every sale line rejection ends with «No se confirmó la venta.».
- **S9 (H9):** a success notice of Sales, Purchases or Movements is cleared when the user leaves the view.
- **S10 (H10):** re-check whether changing the unit clears the typed purchase price; change code only if it reproduces.
- **S11 (review R3-formathints-stale-validity):** a hint set on a field never blocks the submission of a value that became valid without typing (for example a prefilled form).
- **S12 (review R3-lists-unordered-refresh):** overlapping reloads of the price lists apply only the latest answer.
- **S13 (review R3-sales-preconfirm-untested, R3-format-hint-untested):** the pre-confirmation re-read and the format hints are covered by automated tests, including browser stages for H1 and H2.
- **S14 (review R3-total-mismatch-rounding):** the «total difiere del estimado» notice compares exact amounts, never rounded ones.
