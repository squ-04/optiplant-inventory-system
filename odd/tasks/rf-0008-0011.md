# RF-0008–RF-0011 — Product catalog maintenance

Objective: create, query, update and logically deactivate/reactivate products end to end (Spring Boot + PostgreSQL + React).
Branch: `feat/rf-0008-0011` from `main` 8079631. Delivery: work-unit commits, no push. Runners: Maven Docker runner (`backend/README.md`), `pnpm test` / `pnpm build`.

## Specs

- **S1 (RF-0008):** administrator creates products with stable public identity (`externalId` UUIDv4), network-unique SKU, name, optional description and base unit (name, divisibility). «Crear producto no crea stock; administrador puede habilitarlo explícitamente en varias sucursales o todas las existentes, con mínimo explícito por sucursal.» RF-0008-CA-02: «dado un SKU ya existente, cuando se intente crear otro producto con ese SKU, entonces se rechazará sin duplicar el catálogo. Habilitar el producto en otra sucursal conservará su identidad y no incrementará existencias.»
- **S2 (RF-0009):** administrator, manager and operator query products; «distinguir información de producto de existencias por sucursal»; «Consulta no concede mantenimiento ni acceso a valoración restringida.»
- **S3 (RF-0010):** administrator updates allowed attributes; «conservar identidad estable y SKU tras el uso del producto; identidad pública siempre inmutable»; «actualizar atributos comerciales no reactiva un producto por inferencia ni restaura habilitaciones locales o mínimos»; «gerente no mantiene atributos generales».
- **S4 (RF-0011, H v1.3/01):** «La eliminación es exclusivamente lógica mediante desactivación (`active=FALSE`), solo con stock cero en todas las sucursales y sin operaciones pendientes [...]; no se permite borrado físico ni en cascada.» Deactivation disables local enablements and clears minimums in the same transaction (data model §6.2). «Solo el administrador puede reactivarlo; la reactivación restaura su disponibilidad en el catálogo general, pero no lo habilita para operar en ninguna sucursal ni restaura mínimos previos.»

Assumptions (derived, not new scope): minimum quantity is a base-unit decimal string with at most 3 decimals and must be an integer for indivisible products; "use" that protects SKU/base unit = any balance, movement, purchase/sale/transfer line or price entry.
