# RF-0021, RF-0023–RF-0025 — Purchase orders, conditions, receipt and history

Objective: create purchase orders to minimum suppliers with commercial conditions, receive them completely through the shared inventory ledger and consult their history by supplier and product (Spring Boot + PostgreSQL + React).
Branch: `feat/rf0021-rf0023-rf0025` from `main` 2229d64. Delivery: work-unit commits, no push. Runners: Maven Docker runner (`backend/README.md`), `pnpm test` / `pnpm build`.

## Specs

- **S1 (RF-0021, INC-012/D01–D02):** «proveedor reutilizable mínimo con identidad estable, código único y nombre, creado/modificado por administrador. No exigir NIT, domicilio, correo, cuenta bancaria ni datos fiscales.» RF-0021-CA-02: «Rechazar código duplicado sin alterar el catálogo.»
- **S2 (RF-0021):** «Asociar proveedor, productos habilitados y condiciones de RF-0023; creación no incrementa inventario ni genera pagos.» The operator registers purchases of their own branch (§5.2: «Registra/confirma propias»); RF-0021-CA-01: «dados un proveedor y productos identificados, cuando se cree una orden, entonces podrá consultarse con su proveedor, productos y condiciones registradas.»
- **S3 (RF-0021-CA-03, H v1.3/02):** «dado un proveedor con nombre A, cuando se cree una orden en borrador, entonces su nombre histórico será A y no nulo; si el proveedor cambia a B antes de pasar la orden a pendiente de recepción, esa transición actualizará el nombre histórico a B; un cambio posterior a C no modificará B en la orden, tampoco al recibirla o cancelarla.»
- **S4 (RF-0023, INC-012/D03–D05):** «precio unitario bruto por unidad comercial, descuento porcentual por línea entre 0 y 100% (0 explícito), neto no negativo. Plazo entero no negativo en días desde recepción confirmada; conservar vencimiento calculado. COP, sin impuestos, fletes ni conversión de divisas.» RF-0023-CA-02: «dada una caja de 12 unidades base a precio 120 y descuento 10%, cuando se reciba, entonces el neto será 108 por caja y el costo 9 por unidad base; descuento fuera de 0–100% o plazo no entero/negativo se rechazará sin modificar compra ni inventario. Un plazo de cero días vencerá en la fecha de recepción confirmada.»
- **S5 (RF-0024, INC-011/D02,D04):** «confirmar recepción completa de todas las líneas vigentes de orden pendiente, registrando ingresos trazables y valoración una sola vez. Crear orden no sustituye recepción. Repetir petición de una recepción confirmada no incrementa nuevamente stock ni valor.» RF-0024-CA-02: «Intentar recepción parcial no confirmará ni modificará parcialmente la compra/inventario.» Stock changes only through `InventoryLedger` (ARQ PEN-005; L1 user note).
- **S6 (RF-0025, INC-011/D06):** «ambas perspectivas obligatorias; incluir e identificar borradores, pendientes, canceladas y recibidas. Estadísticas de compras realizadas distinguen órdenes de recepciones; no presentar una cancelada como recibida.» Scope: «gerente propio, administrador red, operador registros operacionales propios.»
- **S7 (frontend):** purchases view integrated with the real API, following `docs/08-implementacion/sistema-visual.md`, with loading, success, empty, validation and error states.

Assumptions (technical, not functional): order code `OC-` + zero-padded internal id; payment term limited to 36500 days so the due date never overflows (data model §6.3 «validar plazo y suma de fecha sin desbordamiento»); a repeated receipt with a different key answers 409 `PURCHASE_ALREADY_RECEIVED`, the same key returns the stored result (RF-0024 «contrato API decidirá respuesta existente o conflicto identificable»).

Out of scope (RF-0022, not requested): editing drafts, cancelling orders, replacement orders. CANCELLED orders are still displayed when present.
