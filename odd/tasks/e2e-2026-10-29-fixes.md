## Specs

- **S1 (H1):** opening «Registrar despacho» proposes the current Bogotá time as «Salida real» unless the operator already edited that field while the detail stayed open; carrier and estimated arrival typed before are kept.
- **S2 (H2):** the shortage panel never says that a resend releases the original transit. While transit is pending it says that only the origin manager's transit loss settles it and that a resend is a new transfer that does not release it; once nothing is pending it says so.
- **S3 (H3):** dispatch, rejection and cancellation ask for confirmation in a dialog before calling the server, like approval, reception and transit loss.
- **S4 (H4):** a success notice of Transferencias is cleared when another detail is opened or the list is consulted with new filters.
- **S5 (H5):** the shortage panel labels the opening date «Abierta el»; a reception with nothing received is described as «sin mercancía recibida», never as a partial arrival.
- **S6 (H6):** a rejected or cancelled transfer shows the steps it never reached as not carried out («no realizado»), not as pending.
- **S7 (H7):** Consultas no longer says that purchases, sales and transfers are pending deliveries.
- **S8 (H8):** no «p. m..» double period; a space separates a name from its code; «TR-000001 para»; the shortage line shows the unit of what was sent; the server's surplus message avoids «se despacharon 1 caja».
- **S9 (H9):** a server error without detail reads «El servidor no pudo completar la solicitud (HTTP 500). Vuelva a intentarlo; si persiste, avise al administrador.» instead of «Error HTTP 500.», and the transfers list adds that the rows shown may be outdated.
- **S10 (H10, decided in L5):** master-data codes are unique regardless of letter case (branches, users, product SKUs, price lists, suppliers, routes), keeping the typed spelling; a case-only duplicate gets the same `409` as an exact one; login keeps matching the code exactly; generated codes (`OC-`, `VT-`, `TR-`) are unchanged. The migration never renames, merges or deletes data: on existing collisions it stops before any change and names them.
- **S11 (H11, decided in L5):** `actualSeconds` rounds up like `deviationSeconds`, so deviation = actual − estimated.
- The generic `400` for a non-UUID `branch` comes from the shared handler and stays as is.
